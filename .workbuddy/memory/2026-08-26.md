## 分析 maozi-pet 系统与补全 APK 打包

- **系统架构**：React Native + Expo（前端）/ Node.js + Express + SQLite（后端）/ 阿里百炼 qwen-plus（AI）。CI 仅覆盖后端构建 + 前端 Web 构建（`expo export --platform web`），部署到阿里云 ECS（SSH + PM2 + Nginx）。
- **关键缺口**：原本**完全没有 APK 打包能力**——无 `eas.json`、无 `eas build` 任务、无 keystore、无原生 android/ 目录。README/用户以为 GitHub Action 能打包 APK，实际只构建 Web 版。
- **补全内容**：
  - 新增 `frontend/eas.json`（preview=apk / production=app-bundle 两个 profile，env 中需填 EXPO_PUBLIC_API_BASE_URL 指向真实服务器）
  - 新增 `.github/workflows/build-apk.yml`（EAS Build 云端构建，手动触发或 v* tag 触发，产物以 Actions Artifacts 分发）
  - 更新 `.github/SECRETS.md`（补充 EXPO_TOKEN 说明）与 `README.md` 目录
- **功能实现评估**：后端 6 路由（ai/pet/auth/shop/inventory/social）全部落地且带安全加固（scrypt 密码、JWT、限流、事务、并发防刷、隐私控制）；前端页面 + 3 个 store（pet/inventory/social）+ apiFetch 封装均真实对接后端，非空壳。
- **上线前待办**：需在 GitHub Secrets 配置 EXPO_TOKEN；本地跑一次 `eas build:configure`；把 eas.json 的 API 地址改成真实服务器；后端暂无自动化测试（package.json 无 test 脚本）。

## 修复问题 + 优化（第二轮）

复核代码后修复 4 处缺陷（后端 tsc 与前端 tsc 均通过）：
- `backend/src/routes/shop.ts` `/checkin` 日历：`((day-1)%7)` 在 7 天周期边界（day=0）产生负数索引 → `CHECKIN_REWARDS[-1]` 为 undefined。改为 `((day-1)%7+7)%7`。
- `frontend/src/store/petStore.ts` `sendMessage`：userMessage 已加入 chatHistory 后又被再次追加进 messages，导致最后一条用户消息重复发给 AI。改为直接发送过滤后的 chatHistory。
- `backend/src/routes/social.ts` `/friends/search`：map 中逐用户查 friendships 判断 isFriend（N+1）。改为一次 `IN` 查询收集 friendIds 集合。
- `.github/workflows/build-apk.yml`：下载地址用了 `artifacts.buildUrl`（构建详情网页）而非 `artifacts.applicationDownloadUrl`（真实 APK 文件）。改为 applicationDownloadUrl（带 buildUrl 兜底）并加 `--status finished` 过滤。
